# 主题族：系统/模拟器/升级/游戏 v2.0

> 本主题族装"系统/模拟器/升级/游戏"领域的题材内容——**5 字段只装领域内容**，**不装基底坐标轴**，**不装作家风格**。
>
> **可叠加**：可与基底正交叠加，可与作家风格层独立叠加。**与 cross-time 主题族常叠加**（系统+穿越/反英雄）。

## 领域装置

| 主题 | 领域装置 | 关键特征 |
|------|---------|---------|
| system | 系统面板/技能树/任务 | 游戏机制 |
| simulator | 模拟/读档/命运点 | 模拟机制 |
| level-up | 升级/经验值/属性 | RPG 机制 |
| game | 游戏化世界/规则怪谈 | 游戏世界 |
| achievement | 成就/奖励/称号 | 成就系统 |
| urban-fantasy | 都市+魔法+系统 | 都市奇幻+系统 |

**领域装置 = 场景的"题材空间"**——读者从这个空间里知道这是系统/模拟/游戏故事

---

## 关系

### who（角色类型）

- **system**：主角+系统+配角（3-5 角色——系统是第二叙事声）
- **simulator**：主角+系统+模拟角色（3-5 角色）
- **level-up**：主角+队友+对手（5-10 角色）
- **game**：玩家+NPC+规则（5-15 角色）
- **achievement**：主角+系统+成就证明（3-5 角色）
- **urban-fantasy**：主角+魔法存在+普通人（5-10 角色）

### 障碍（关系冲突源）

| 障碍 | 主题相关 |
|------|---------|
| 信息差（仪式/系统不为人知）| system/simulator 强 |
| 系统不透明 | system 强——系统的运作规则是黑箱 |
| 时间压力 | simulator 强——24h 倒计时 |
| 命运点扣减 | simulator 强——每次失败扣分 |
| 等级差距 | level-up 强——等级压制 |
| 规则冲突 | game 强——规则怪谈 |

## 推进单位

| 主题 | 推进单位 | 跨章衔接 |
|------|---------|---------|
| system | 一次系统事件+一次结算 | 系统延续+新任务 |
| simulator | 一次模拟（24h 倒计时）| 模拟延续+命运点扣减 |
| level-up | 一次升级/一次战斗 | 升级延续+新挑战 |
| game | 一次游戏事件+一次规则揭示 | 游戏延续+规则推进 |
| achievement | 一次成就+一次奖励 | 成就延续+新目标 |
| urban-fantasy | 一次都市+魔法事件 | 都市延续+魔法事件 |

**推进单位 = "一章至少完成一次什么"**——明确读者读完一章能拿到的最小系统/模拟推进

## 高潮模式

| 主题 | 高潮类型 | 收束模式 |
|------|---------|---------|
| system | 系统结算型 | 系统评价+奖励+命运点扣减+技能升级 |
| simulator | 系统结算型 | 评价+奖励+命运点扣减+技能升级 |
| level-up | 信息揭露型/系统结算型 | 等级突破+战斗胜利 |
| game | 信息揭露型/启示式 | 规则真相揭示+游戏结局 |
| achievement | 角色选择型 | 成就完成+奖励+责任 |
| urban-fantasy | 信息揭露型/系统结算型 | 都市+魔法真相揭示 |

**高潮模式 = "系统/模拟推进到顶点的形态"**——读者期待的"那一下"是哪种

**高潮发生位置**：
- 系统结算型——在一次系统事件末尾，系统评价+奖励+命运点扣减+技能升级
- 信息揭露型——在一次游戏/规则事件末尾，真相揭示
- 等级突破——在一次升级末尾，角色获得新能力

## 失效模式（写作时避坑）

- ❌ 把"领域装置"写成抽象名词——✅ 写具体可感的物（系统面板/技能树/任务窗口）
- ❌ 把"障碍"写成"内心冲突"——✅ 写可观察的具体事件（信息差/系统不透明/时间压力）
- ❌ 把"高潮模式"写成"情绪爆发"——✅ 写具体动作（系统结算/等级突破/规则真相）
- ❌ system 主题无系统面板——✅ system 必须有面板/技能树/任务等系统元素
- ❌ simulator 主题无时间压力——✅ simulator 必须有倒计时/读档/命运点
- ❌ system 主题变成金手指——✅ system 应当是"工具"而非"全能解"（反英雄特色）

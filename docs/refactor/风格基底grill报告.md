# 风格基底 Grill 报告（v1.0 → v1.1 修订建议）

> **核心目的**：对 2 风格基底做元层面审查——分清"基底特性/风格/过度提取"三层，给出 v1.1 修订建议。
>
> **3 层定义**：
> - **基底特性**（Base）= 跨作家跨题材普遍适用，工程级"基线"——是工具的默认配置
> - **风格**（Style）= 单作家或题材的特定选择——是工具的"主题/变体"
> - **过度提取**（Over-extraction）= 分析时从作品细节过度泛化，与文本证据不匹配 或 工程不可消费
>
> **判定标准**：
> - 文本证据：是否有 3 作家（或 3 题材）共同数据支持？
> - 工程可消费性：是否能被 mo-writer/sensory-writer/chapter-review 等 Skill 直接消费？
> - 边界明确性：与变体的边界是否清晰？
> - 必要性：作为基线，缺了它会破坏写作流吗？

   - 工程上避免"把具体作家的特征误作为共性基底"——这是导致基线"过载"的根因
   - 让基线"轻"而"准"——基线只装跨作家共性，作家特定放变体

# C11：正式层 mtime 一致性

## 检查逻辑

比对 `novel/` 设定文件 mtime 与 `novel/_changes.md` 最后 `merged_at` 时间戳，防止人工手改正式层设定文件导致日志与文件脱节。

**扫描范围**：`novel/` 根设定文件（`characters/*.md` / `world/*.md` / `outline.md` / `author-voice.md` / `voice-bible.md` / `style-guide.md` / `vocabulary-bank.md` / `thread-map.md` / `character-arcs.md` / `project-config.md`）。

**判定规则**：

1. 读 `novel/_changes.md` 最后一条记录的 `merged_at` 时间戳 T_last
2. 对每个设定文件 F，取 mtime(F) = T_F
3. 比对：
   - T_F ≤ T_last + 容差（如 60s，覆盖 merge 写入抖动）→ ✅ 一致
   - T_F > T_last + 容差 → ⚠️ 警告：文件 F 在最后一次 merge 之后被修改，可能是人工手改

**容差说明**：merge-settings 写入 `novel/` 设定文件 + 追加 `novel/_changes.md` 不是原子的（两阶段暂存-提交的提交阶段内顺序写入），容差 60s 覆盖正常 merge 抖动。

## 触发条件

- 永远（写作/改编/审阅前都跑），但 `novel/_changes.md` 不存在时（项目首次启动，无 merge 历史）→ 跳过，状态 ℹ️
- `novel/` 不存在 → 跳过（由 C3 处理）

## 阻断等级

⚠️ 提醒——不阻断。人工手改正式层设定文件违反"正式层不可手改"约束，但可能是用户有意为之（如紧急修正）。提示用户：

> 正式层设定文件 {F} 在最后一次 merge（{T_last}）之后被修改（mtime={T_F}）。
> 正式层设定文件应通过 publish-chapter merge 更新，不可手改。
> 如需保留修改 → 回滚 _changes.md 追加对应变更条目；如需丢弃修改 → 从 _backup/ 恢复。

## 输出

每个不一致文件一行：`{文件路径} | mtime={T_F} | last_merge={T_last} | 漂移={秒数}` + 总计 N 个文件漂移。
